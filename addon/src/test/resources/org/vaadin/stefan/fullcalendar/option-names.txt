# The library option names the core add-on supports, one per line: the name, then "global" or "view".
#
# A global option has its field in CalendarOptions, a per-view option in ViewOptions. Every name not shown as global
# below is per view. Generated once from the non-deprecated constants of org.vaadin.stefan.fullcalendar.Option, with
# "class" written as "className".
#
# A name is global when the library reads it only from the calendar options, so a per-view value has no visible
# effect, or when the add-on chooses so. To check a name, search the library source in e2e-test-app/node_modules for
# its readers. If only the calendar options or the calendar context read it, it is global. If a view reads it too,
# so a per-view value changes behaviour or display, it is per view. One exception: direction stays global, although
# a view reads it, because that read only sets the text direction of an entry while it is dragged.
#
# Global by the library source:
# - the inputs of buildDateEnv: timeZone, locale, weekNumberCalculation, firstDay, weekTextLong, weekTextShort
# - the toolbar. parseToolbars reads headerToolbar, footerToolbar, direction and toolbarElements. getButtonState reads
#   buttons and the button texts and hints. The view buttons read listText through the view's buttonTextKey, and
#   dayText and monthText through getSingleUnitText. The calendar root also sets its text direction from direction.
# - CALENDAR_ONLY_OPTION_REFINERS: className, viewClass, viewDidMount, viewWillUnmount
# - initialView and initialDate, read when the calendar is created, and rerenderDelay
# - buildViewUiProps, which gets the calendar context: eventDisplay, eventStartEditable, eventDurationEditable,
#   eventConstraint, eventAllow, selectConstraint, selectAllow
# - fetching entries, which uses the calendar context: eventDataTransform, lazyFetching, eventSourceSuccess,
#   startParam, endParam, timeZoneParam, and googleCalendarApiKey in @fullcalendar/google-calendar
#
# Global by the add-on's choice:
# - the calendar listeners of CALENDAR_LISTENER_REFINERS, because the add-on registers them itself. Of these only
#   loading has an Option constant.
# - the options the add-on handles itself: eventDidMount, moreLinkClick
#
# Per view, because a view reads them as well as the calendar options: editable (whether
# a view takes entries dropped from another calendar), selectOverlap (its function form), eventOverlap and
# businessHours (also for the display), visibleRange, the toolbar class options and buttonDisplay (the toolbar renders
# in the view context). defaultAllDay is read only by computeIsDefaultAllDay, through parseEvent. The contexts its
# callers pass (the event sources, addEvent, normalizeConstraint) were not all traced, so it stays per view. If they
# all pass the calendar context, defaultAllDay is global.
#
